**太虚异劫**

**Web 试玩版需求规格说明书**

Three.js / React Three Fiber · Vertical Slice

版本：v0.1  
日期：2026-10-01  
定位：浏览器可直接运行的 10～15 分钟高质量动作试玩版

**核心体验：修仙巨构 × 黑雾异变 × 动作战斗 × 鲲鳌巨物感**

# 1. 文档目的

本需求文档用于指导 Codex / 人工协作完成《太虚异劫》Web Vertical
Slice。试玩版不是临时展示页，而是用于验证核心玩法、世界观、动作手感、巨构尺度与巨物演出的正式原型。成熟的
3D 资产、骨骼动画、音频与数据定义应尽可能可复用于后续 Unreal Engine 5
正式版本。

## 1.1 产品定位

| **项目** | **定义**                                                  |
| -------- | --------------------------------------------------------- |
| 类型     | 第三人称 / 第一人称可切换的 3D 动作冒险试玩版             |
| 题材     | 东方修仙巨构世界遭遇域外黑雾与不可名状生命侵蚀            |
| 平台     | 桌面浏览器优先，Vercel 部署                               |
| 单次体验 | 10～15 分钟                                               |
| 目标玩家 | 喜欢修仙、巨构、动作战斗、怪谈 / 宇宙恐怖与探索体验的玩家 |
| 最终目标 | 验证核心体验，为后续 UE5 正式版提供设计与资产基础         |

## 1.2 成功标准

- 玩家进入 30 秒内能感受到宗门巨构尺度，而不是“普通古风建筑群”。

- 第一 /
  第三人称切换稳定，第三人称适合战斗，第一人称适合观察巨构和恐怖细节。

- 角色具备基础但完整的动作反馈，包括移动、三段轻攻击、重攻击、闪避、受击与死亡。

- 黑雾入侵不是单纯换天空盒，而是伴随环境、音效、敌人和巨物事件逐步升级。

- 鲲与巨鳌在 Demo 中主要作为巨型事件和叙事锚点，能够产生明显尺度压迫。

- Vercel 线上版本可稳定打开，不要求用户安装客户端。

# 2. 世界观与故事范围

故事发生在云海之上的太虚仙宗。宗门由巨型山门、悬空主殿、侧塔、飞桥、浮空山峰与云海构成。鲲游弋于宗门外云域，巨鳌沉眠于仙山下方。某日天边出现逆风而行的黑雾，随后宗门灵兽、弟子与建筑开始受到感染。

## 2.1 Demo 剧情节拍

| **阶段**      | **玩家体验**                    | **关键演出 / 系统**                        |
| ------------- | ------------------------------- | ------------------------------------------ |
| A. 平静宗门   | 出生于山门外，学习移动与视角    | 正常云海、钟声、远景鲲、完整仙宗轮廓       |
| B. 黑雾初现   | 向主殿推进，天色逐渐异常        | 天边黑雾、环境光变化、远处钟声中断         |
| C. 第一波感染 | 遭遇 2～3 名异常弟子            | 基础战斗教学、受击与处决反馈               |
| D. 鲲发狂     | 抵达开阔平台，鲲突然冲出云海    | 巨型 SkinnedMesh、云海扰动、镜头与音效演出 |
| E. 污染加深   | 穿过半感染宗门区域              | 材质污染参数、菌丝 / 裂纹 / 红黑脉络       |
| F. 御剑段落   | 短距离高速跨越断裂区域          | 御剑飞行、巨构近距离掠过                   |
| G. 小型 Boss  | 击败一名高阶异化弟子 / 守门灵兽 | 完整战斗闭环                               |
| H. 巨鳌苏醒   | Boss 后地面震动，远处山体移动   | 甲壳、眼睛、云海翻腾、Demo End             |

## 2.2 本版本明确不做

- 完整开放世界。

- 完整 RPG 数值成长与装备系统。

- 复杂任务树、NPC 日常与对话系统。

- 鲲或巨鳌完整 Boss 战。

- 多人联机。

- 完整 Motion Matching、复杂全身 IK、攀爬系统。

- 大规模可破坏建筑。

- 移动端完整适配。

# 3. 核心玩法需求

## 3.1 玩家控制

| **输入**   | **功能**            | **说明**                               |
| ---------- | ------------------- | -------------------------------------- |
| WASD       | 移动                | 相机相对方向移动                       |
| Shift      | 冲刺                | 提高移动速度并切换 Run / Sprint 动画   |
| Space      | 跳跃                | 基础跳跃，第一版不做复杂空中动作       |
| V          | 第一 / 第三人称切换 | 平滑相机过渡，不切换 Pawn              |
| 鼠标       | 观察 / 转向         | 第三人称控制镜头，第一人称直接控制视角 |
| LMB        | 轻攻击              | 支持三段连击                           |
| RMB        | 重攻击 / 防御预留   | v0.1 默认重攻击                        |
| Alt / Ctrl | 闪避                | 带短暂无敌窗口                         |
| Q          | 锁定目标            | 第三人称战斗使用                       |
| F          | 互动                | 关键触发点、调查点                     |
| R          | 御剑切换            | 指定剧情段落开放，不做全地图自由飞行   |
| Esc        | 暂停 / 设置         | 音量、灵敏度、画质档位                 |

## 3.2 第一 / 第三人称系统

- 同一个 Player
  实体共享移动、生命、战斗、武器与状态，不创建两套角色逻辑。

- 第三人称：完整人物网格、Spring Camera、目标锁定、战斗镜头辅助。

- 第一人称：相机挂接头部 Anchor，隐藏或裁剪头部，尽量保留身体可见性。

- 切换过程建议 0.25～0.4 秒插值，避免瞬切造成眩晕。

- 第一人称不要求所有近战动画达到 FPS
  专用标准，但必须避免明显穿模、镜头进入头部或武器遮挡全屏。

## 3.3 战斗系统

| **模块** | **v0.1 要求**                                              |
| -------- | ---------------------------------------------------------- |
| 轻攻击   | Attack01 → Attack02 → Attack03 三段连击，带 Combo Window。 |
| 重攻击   | 独立前摇与更高伤害，可打断普通敌人的部分行为。             |
| 闪避     | 位移 + 动画 + 短暂无敌帧，消耗少量体力或使用冷却。         |
| 命中检测 | 武器 Hitbox / Sweep，仅在 Anim Event 指定窗口启用。        |
| 打击反馈 | Hit Stop、Camera Shake、受击动画、VFX、SFX，均可调参数。   |
| 锁定     | 第三人称支持最近目标锁定与解除，第一版不做复杂目标循环。   |
| 敌人状态 | Idle / Patrol / Chase / Attack / Hit / Dead。              |
| Boss     | 至少 3 种攻击模式 + 硬直 / 受击 + 第二阶段视觉变化可选。   |

# 4. 角色与骨骼动画需求

## 4.1 玩家最低动画集

| **类别**     | **动画**                                                                  |
| ------------ | ------------------------------------------------------------------------- |
| Locomotion   | Idle、Walk、Run、Sprint、JumpStart、JumpLoop、Land                        |
| Combat       | Attack01、Attack02、Attack03、HeavyAttack、Dodge                          |
| Reaction     | HitFront、HitBack 或简化为 Hit、Death                                     |
| Sword Flight | MountSword / SwordIdle / SwordForward / DismountSword，可先简化为 2～3 条 |

- 统一 Skeleton，所有玩家动作必须基于同一骨架。

- 动画必须具有可识别命名，禁止 Untitled_Action.001 一类最终命名。

- Web 版优先使用 In-Place
  Locomotion。攻击动画允许带轻度位移，但运行时需避免与角色控制器冲突。

- 动画切换使用 CrossFade，不允许大范围直接硬切。

## 4.2 鲲与巨鳌动画策略

- 鲲：必须使用骨骼网格或分段骨骼结构，至少包含 Swim、Rage、Surface /
  Breach、Turn。

- 巨鳌：v0.1
  不要求完整可探索网格。使用大体量模型片段、甲壳、眼部、地形位移假象与镜头演出组成苏醒事件。

- 巨物在 Web 版以视觉事件优先，不做高频复杂碰撞。

# 5. 场景与视觉需求

## 5.1 场景构成

| **区域**        | **作用**                                          |
| --------------- | ------------------------------------------------- |
| 巨型山门        | 出生区与尺度建立，保留既有修仙巨构语言。          |
| 千级石阶 / 主轴 | 引导玩家向核心区域推进。                          |
| 主殿外平台      | 鲲发狂事件的最佳观看点。                          |
| 侧塔 / 飞桥     | 形成高低差和御剑飞行路径。                        |
| 污染区          | 展示建筑和弟子逐步异化。                          |
| Boss 平台       | 有清晰边界、足够战斗空间、远景可看到主殿 / 云海。 |
| 云海下层        | 用于鲲穿行、巨鳌局部显现与深度错觉。              |

## 5.2 黑雾与感染表现

- 黑雾应具有明确推进方向与区域边界，不能只是统一屏幕滤镜。

- 环境感染参数 corruption 建议统一为
  0～1，可驱动材质混合、颜色、发光、粒子密度和音效强度。

- 宗门建筑保持原有白石 / 金饰 /
  云海视觉基底，污染是在同一建筑上逐步叠加，而不是换成另一套地图。

- 感染视觉关键词：黑红脉络、异常菌丝、裂缝、局部肉质结构、异常眼器，但避免所有表面都变成同一种“触手贴图”。

## 5.3 巨构尺度原则

- 玩家高度约 1.7～1.9m，山门、主殿、石阶必须维持明确比例参照。

- 通过近景栏杆、门柱、台阶、树木、弟子 NPC 等建立连续尺度链。

- 远景建筑不能全部缩成背景贴片，关键主建筑需保留足够体积与层次。

- 相机 FOV、雾、飞行速度和镜头高度必须服务于“巨大”而非单纯扩大模型。

# 6. 敌人与 Boss 需求

| **敌人**         | **数量 / 定位**                        | **最低行为**                                    |
| ---------------- | -------------------------------------- | ----------------------------------------------- |
| 异化弟子         | 主力小怪，至少 1 种模型或 2 种材质变体 | 巡逻、发现、追击、近战攻击、受击、死亡          |
| 污染灵兽（可选） | 增强场景变化                           | 冲撞或跃击                                      |
| 小型 Boss        | Demo 终局战斗                          | 至少 3 种攻击、追击、受击、死亡、阶段性视觉变化 |
| 鲲               | 背景级巨物                             | 游动、冲出云海、发狂、掠过建筑                  |
| 巨鳌             | 结尾事件                               | 局部苏醒、震动、甲壳移动、睁眼                  |

## 7.2 架构约束

- 避免将所有逻辑塞进单一 World.tsx / App.tsx。

- Gameplay 与渲染表现解耦。战斗状态、伤害、动画事件与 VFX
  参数应通过明确接口连接。

- 资产路径、敌人属性、技能参数尽量数据化，减少硬编码。

- 必须提供 Debug HUD 或开发面板，用于显示
  FPS、玩家状态、当前动画、目标、污染参数与事件阶段。生产构建默认隐藏。

# 8. 性能与浏览器约束

性能目标以“主流桌面独显浏览器可流畅试玩”为准，不以旗舰 GPU
为唯一基准。具体预算在首轮性能测试后允许调整。

| **指标** | **初始目标**                                                             |
| -------- | ------------------------------------------------------------------------ |
| 帧率     | 1080p 中等质量：目标 60 FPS；复杂演出最低尽量保持 45 FPS 以上            |
| 首屏     | 优先加载最小启动场景与 UI，避免一次性等待全部资源                        |
| 资产加载 | 场景分区 / 按需加载，鲲、Boss、巨鳌等按剧情阶段预加载                    |
| 纹理     | 优先 1K～2K；核心角色 / Hero Asset 可有限使用更高分辨率                  |
| 网格     | 高模必须经过 Blender 优化，禁止直接把百万级 Tripo 原始网格大规模塞入场景 |
| 阴影     | 限制实时投影灯光数量；远景与非关键资产使用简化方案                       |
| 粒子     | 黑雾粒子必须设置最大数量与距离裁剪                                       |

# 9. 资产生产与 UE5 迁移约束

所有可复用资产应遵循“Tripo / 其他来源 → Blender 清理 → 标准资产 → Web /
UE 分发”的流程。

| **类别**    | **Web 输出**            | **UE 迁移准备**                                          |
| ----------- | ----------------------- | -------------------------------------------------------- |
| 角色 / 怪物 | GLB + Skeleton + Clips  | 保留 Blender 源文件与可导出的 FBX / GLTF                 |
| 建筑        | 优化后的 GLB / 分块 GLB | 保留高低模与材质源文件                                   |
| 动画        | AnimationClip           | 统一骨架、统一命名、保留原始动作                         |
| 纹理        | Web 压缩格式            | 保留 BaseColor / Normal / Roughness / Metallic / AO 源图 |
| 音频        | Web 压缩音频            | 保留无损源文件                                           |

- 世界单位统一按 1 unit = 1 meter 设计。

- 每个资产必须明确 Pivot、Scale 与朝向。

- 禁止只保留压缩后的 Web 版本，必须保存源资产。

- 后续迁 UE 时允许重做材质、VFX、Gameplay 与动画运行时，不要求复用
  Three.js 代码。

# 10. 音频需求

- 正常宗门：风、云海、远处钟声、低密度环境音。

- 黑雾出现：加入低频持续音、不可辨识低语、远处金属 / 石质共振。

- 鲲事件：超低频巨兽鸣叫、云海冲击、建筑震动。

- 战斗：剑击、命中、闪避、受击、脚步、衣料 / 武器移动声。

- 巨鳌苏醒：地震、岩石摩擦、极低频呼吸或共鸣。

- 提供 Master / Music / SFX 三类音量控制。

# 13. 最终验收清单

- 首次打开无需本地安装，可进入游戏。

- 第一 / 第三人称至少连续切换 20 次无状态错乱。

- 玩家移动、跳跃、冲刺、攻击、重击、闪避、锁定均可完成。

- 三段轻攻击存在明确连击窗口，不会无限重复触发伤害。

- 至少完成一次异化弟子战斗与一次 Boss 战。

- 黑雾从远景到进入宗门有清晰叙事阶段。

- 鲲事件具有动画、音效和环境反馈，不只是静态模型移动。

- 巨鳌苏醒能够明确传达“宗门山体建立在巨型生命之上”的信息。

- 试玩过程中无阻断流程的报错、角色掉出世界、无法继续等问题。

- 开发态 Debug 信息不会出现在公开构建中。

# 14. Codex 实施原则

- 先完成可玩的纵向闭环，再增加内容，不提前扩张为开放世界。

- 每个阶段结束必须运行 lint / typecheck / build，并通过实际浏览器试玩。

- 大改前先分析现有架构和风险，优先修改而不是重复创建平行系统。

- 核心状态机、动画、战斗、事件必须有清晰接口和最小必要注释。

- 新增复杂技术前先证明需求无法由现有系统满足，避免过度工程化。

- 阶段进展写入 PROGRESS.md，记录：完成项、验收、遗留问题、下一步。
